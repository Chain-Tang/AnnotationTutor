# 多 Tutor 的 Markdown 记忆：已有方案与本轮取舍

核查日期：2026-10-17（Asia/Shanghai）。本页依据下列论文正文、项目官方文档，以及本仓库本轮工作树。它记录设计借鉴；代码已加入、测试通过、真实多库部署验收是不同状态。

**建议把 Markdown 用作可阅读、可更正的共同目标、背景和阶段摘要；消息投递、身份权限、版本冲突与凭据则由程序检查。** 文件保存成功之后，还要有明确的检索和上下文注入过程，内容才会影响下一轮回答。多个 Tutor 看到同一个文件名，也不会因此自动拥有相同记忆。

## 读取的基线

已只读检查从课程取回的三份材料：[用户工作流](baseline-2026-10-16/user-workflow.md)、[实现核查](baseline-2026-10-16/implementation-audit.md)、[协作契约](baseline-2026-10-16/collaboration-contract.md)。它们描述升级前状态，并保留“来源、目标、版本、授权和轮次交接”的边界；其中单一可变连接、尚无通信空间等结论应与本轮新增实现对照，不能继续当成升级后的实时状态。

## 已有研究能帮助解决什么

| 实读来源 | 可借鉴的机制 | 对 Tutor 的含义与边界 |
| --- | --- | --- |
| Packer 等，*MemGPT: Towards LLMs as Operating Systems*（2023；v2 为2024），[论文 §2.1–2.4](https://arxiv.org/html/2310.08560v2) | 将有限的当前上下文与外部存储分开，通过工具显式调入相关记忆；临近容量上限时整理和移出旧消息 | 应记录本轮实际带入的摘要、原文范围与截断情况。分层存储本身不提供跨库共享许可，也不保证每次取回完整、正确的内容。 |
| Park 等，*Generative Agents: Interactive Simulacra of Human Behavior*（2023），[论文 §4.1–4.2、§6.5](https://arxiv.org/html/2304.03442v2) | 以相关性、近期性和重要性检索经历；将带原始记录指针的反思作为另一类记忆 | 可借鉴“检索后归纳，并保留依据”。论文评估的是模拟行为可信度；反思属于模型推断，不能自动升级成学习者事实、稳定掌握或心理判断，论文亦报告了记忆遗漏和内容添补。 |
| [OpenClaw 官方 Memory 文档](https://docs.openclaw.ai/concepts/memory)（本日读取） | 区分精简长期 Markdown 与日期笔记，按需搜索、读取；区分磁盘原件与实际注入的预算；对来源、更新和行动条件作说明 | 文件格式适合 Obsidian 人工审校。借鉴“精简摘要＋细节索引＋来源”，并把授权与沙箱作为独立执行机制。文档中的自动整理机制属于该项目，不能视为 Tutor 已实现。 |
| [Claude Code 官方 Memory 文档](https://code.claude.com/docs/en/memory)（本日读取） | 用 `MEMORY.md` 索引与主题文件组织项目记忆，按需读细节；明确机器本地范围与启动加载上限 | 可借鉴索引和按需读取，避免每轮载入全部资料。产品的自动加载规则由其宿主实现；在 Obsidian 创建同名文件不会让 Tutor 或 Codex 自动读取。 |

以上是方法对照，没有引入这些项目为运行依赖，也没有读取它们的本机私有记忆目录。对记忆文件的访问仍应依赖用户授权和相应工具边界。

## 下一步宜怎样推进

先用一个共同学习问题检验完整链路：记录空间版本与授权成员，Tutor A 主动提问，Tutor B 或已绑定的 Codex 收到有限背景并回答；重启后查询原消息和投递状态；修改共同背景后检查旧版本消息；撤销成员后确认新读取和发送被拒绝。这样的用例能同时核验主动通信、记忆延续和权限。

在这条链路稳定后，再为 Markdown 增加检索索引。每条可延续的结论至少保留来源库、路径或消息标识、读取版本、记录者和当前状态；原文变更时标为待复核。若增加反思，应把它当作带依据的建议，保留异议和未知。检索相关性、反思流畅度与权限有效性要分别测试，不能用“两个代理互相回复了”替代全部验收。
