## 2. 实施与安全边界

保存批注后立即显示已保存提示，但只在 authority Markdown 写入成功之后；索引刷新仍可等待与重试，不以未受监管的后台任务替代持久化。普通刷新只重读脏文件或 watcher 提供的路径，派生关系仍从一致的内存资料重算，因此消除了反复磁盘扫描，未宣称所有计算都变为 O(1)。

点评同一批注在入队和运行期间都防重复。失败只恢复仍由请求占有的状态；已写入点评、归档或来源缺失等外部更新保留。成功写点评后，如果记忆单元或派生输出失败，不撤销已保存点评。

预翻译首批先检查凭据，后续 API 请求最多两路；ACP 不复用带历史的聊天会话。按原文批次顺序合并重复词，不用完成顺序决定词义；删除、重命名、目标语言变化与正文变化不会把旧结果标记为新缓存。Direct API 并发仍属于真实的多次模型调用，本轮只用模拟模型验证调度，没有真实费用或长文速度实测。

`pnpm package` 在发布锁内重新构建扩展，再封存插件目录和 ZIP；验证清单比对每个 ZIP 条目的目录字节、可移植路径、必需平台文件、扩展资源、字体和依赖许可证，拒绝配置文件或 source map。非 watch 构建压缩不影响离线字体及许可证。

## 4. 后续分批升级

1. **源码归档与远端验证**：先审查新增源码/测试/脚本/字体许可证，保留真实研发材料，排除本机资料和嵌套候选快照，再形成分批提交与推送。不能用 `git add -A` 将此前数十天的所有未跟踪资料直接发布。本轮忽略规则不会自动清理已跟踪文件，也不是全库隐私审计证明。
2. **启动延迟量化**：凭据迁移和绘图事务恢复决定授权边界，必须在暴露相关操作前完成。当前已有部分 layout-ready 初始化；先测量剩余耗时，再将可选服务按依赖图分批移动，避免画板/学习尚未恢复便接受写入。
3. **渐进拆类与设置局部刷新**：先扩充 Studio 保存、AI 面板和切换/卸载覆盖，再拆编排；设置页按依赖区块更新并验证焦点/滚动恢复。AST 核验当前 BoardLayer 为 119 方法/114 字段，StandaloneBoardView 为 88 方法/91 字段；报告把全部成员当方法。巨型文件行数本身不足以证明错误，不开展无验收保障的大范围改写。
4. **coverage**：当前未安装 coverage provider，无实测基准。本轮没有添加拍定的百分比阈值或用缺失工具阻断原检查；先对关键事务与宿主边界建立可复跑覆盖基线，再逐步门禁。
5. **字体/locale/ACP**：字体已分片但仍需保持离线中文、日本语与手写排版完整性；locale 同步调用遍布视图，懒载需设计初始化契约；点评使用独立 prompt，持久 ACP 池需隔离历史、权限和取消，不能直接复用正在聊天的会话。
6. **历史产物治理**：先验证 ZIP/源码基线/恢复清单一致并确定归档目的地，再移动历史资料；不删除正在承担私有状态恢复或程序回退的基线。
