# 私有凭据与受管理恢复

本说明适用于随当前恢复工具封装的脚本。历史 0.4.6、0.5.3 仅是数据兼容检查对象，不是已通过商业就绪门槛的稳定回退基线。相同版本号也可能对应不同程序：工具核对封存文件哈希，以及与程序字节绑定的 `credential-compatibility.json`。

## 回退及恢复连接

画板事务日志另有 `surfaceTransactionJournalId`，保存在 state 目录外的设置中。已绑定后，日志、标记缺失或身份不一致会暂停 Agent 修改，不新建空日志。受管理降级也会在恢复清单中保留此身份（即使没有 API 凭据）；旧程序丢弃该字段后可在重升时恢复，当前已有不同身份则停止恢复。兼容程序明确删除的身份不从旧清单复活。这不覆盖用户同时删除设置绑定和全部状态的情况。

正常回退命令（替换为自己的绝对路径）：

```sh
node scripts/install-dev-plugin.mjs --vault /absolute/vault --rollback /absolute/private/installation-backup
```

在线模式先等待保存、停止 Tutor 任务和服务、停用插件，再替换程序和检查加载状态。保存或草稿保护失败会阻止卸载。Obsidian 不能启动时，先完全退出所有 Obsidian 窗口，再增加 `--offline`；离线模式只能检查文件，不能证明宿主加载成功。当前在线 CLI 入口适用于 macOS，其他平台须离线恢复或另行验证宿主入口。

已迁移的密钥仍在原宿主系统加密存储中，工具不解密、不导出，也不读取旧备份的密钥。当前引用继续保留于 `data.json`，另在插件目录的 `state/credential-reference-recovery-v1.json` 保留引用、对应旧程序哈希及有限的引擎枚举/功能布尔快照，防止旧程序保存设置时丢掉未知字段。清单还保留非敏感的 `surfaceTransactionJournalId`；没有任何凭据引用、但已有绘图事务身份的安装也会建立该清单。清单不含密钥、模型 ID、端点或命令文本。回退关闭 Clipper、MCP 和新学习外部入口，清除旧 `webBridgeToken`、`androidInkToken`，保留新的客户端授权及撤销记录、当前画作和学习文件。

有凭据引用的旧版会临时将对话、画板、评审、网页分析引擎设为 API；没有明文 key 时正常模型请求会提前拒绝。关闭自动评审、预翻译、网页自动分析、主动关怀、学习专家、云笔迹识别及图片生成。模型 ID、base URL、命令均保持原值。兼容重升仅在这些字段仍等于工具写入的降级值时恢复原枚举/布尔值；用户或旧程序改动任一受保护字段时，整个自动恢复停止并只列冲突字段名。用户可保留现状，或确认后将这些字段改回降级值再重升；不要覆盖整份配置。Clipper/MCP 等外部服务及旧共享 token 不自动恢复。

**旧程序只能承诺本地功能。不要在旧版设置中重新填写密钥：旧版可能明文保存，不能称为仅会话输入。** 恢复连接时使用经过验证、支持引用的完整封存包：

```sh
node scripts/install-dev-plugin.mjs --vault /absolute/vault --source /absolute/compatible-release/annotation-tutor-lite --require-credential-refs
```

该命令只恢复引用，不自动重新开启外部服务。它要求仍为同一 Vault 路径、同一宿主系统安全存储；跨设备引用不能读取时，应在兼容新版中重新配置。新版系统存储不可用时才支持仅会话输入。旧版中若加入了明文密钥、引用冲突、恢复清单损坏或程序被手工更换，自动合并会停止；保留全部原文件，先在本机私有位置封存当前配置，再通过兼容新版和人工核对处理冲突。不要将明文配置发给支持人员，也不要把整个旧 `data.json` 覆盖回来。

若阻塞原因仅为旧版中新填的明文，用户确认放弃这些具体输入后，可在 Obsidian 完全退出时本地编辑当前 `data.json`，只移除相应的 `apiKey`、`boardImageApiKey`、`tutorRemoteToken`、`mcpServersJson` 字段，保留引用清单和其他配置，再执行上述兼容包安装命令。工具没有自动丢弃这些输入的开关。仍需使用的新密钥应在兼容新版中重新填写；不要将它写回历史程序配置。

新版本取消或更换的引用不会从旧恢复清单自动复活。只有恢复清单记录的旧程序哈希仍匹配时，重升才使用该清单；回退前若已处于兼容新版，以当前引用为准。若当前安装与中断时的上一目录都丢失，工具拒绝从备份自动恢复配置，应保留现场并人工恢复当前数据。

绘图事务身份同样以当前兼容版配置为准：兼容版删除、清空或更换身份后，不会复活旧清单中的身份。旧版重写配置丢失该字段时，受管理重升恢复同一身份；当前非空身份与封存身份不同，或身份格式损坏时，停止自动切换并保留原文件。恢复身份不重建事务日志；重升后的身份校验仍会拒绝缺失或不匹配的 journal，不会把遗失的日志当作新的安装。

未完成安全迁移的旧配置会原样保留，并明确显示 `legacy-unmigrated`；工具不替它加密，也不把它报告为已完成迁移。历史安装备份的 `before/data.json`、源码/运行私有基线和同步历史可能仍含旧明文。用户可以在确认恢复成功后自行清理、调整保留期并轮换旧密钥。迁移不会远程清除同步服务的历史版本。应用私有目录中的 `Tutor/private-credentials/<vault-hash>` 与 `Tutor/private-support` 分开；恢复工具不复制支持摘要，也不清理这两个目录。

## 崩溃遗留锁

正常运行不按时间判断锁过期。先退出所有 Obsidian 窗口以及正在构建、安装或打包 Tutor 的进程；只对本机文件系统执行下列命令，不用于共享目录另一台机器的锁。

```sh
node scripts/recover-private-state.mjs --lock /absolute/plugin/data.json.credentials-write.lock
```

发布锁同样支持：传入实际的 `*.tutor-release-lock` 目录（例如插件相邻的生命周期锁或 `dist/artifacts.tutor-release-lock`）。诊断只返回类型、PID 存活状态、指纹和处理建议，不读取配置或密钥。

同一命令也接受 `state/` 下的五类固定状态锁：绘图事务日志及其初始化标记、Clipper 配对策略、客户端授权和请求回执的 `.lock` 文件。仅恢复锁，不重建或清空日志。未知状态文件名、早期没有 PID 的锁仍须人工核对，不按文件年龄删除。

新版私有关怀摘要使用独立的 `Tutor/private-support/<vault-hash>/support-write.lock`，同样只诊断所有者与指纹，不读摘要或解密。不同窗口共用宿主会话，文件写入串行；另一进程或崩溃遗留锁不按时间抢占。完全关闭所有相关进程后，才能用下述明确恢复命令处理该固定锁。私有目录不进入常规发布、导出或回退包。

摘要删除与到期清理会先将旧版可读取的 `summaries.enc` 移为加密的 `summaries.suspended.enc`，再写入加密撤销记录，并保存剩余摘要。若剩余文件写入失败，删除保持失败提示，旧版不会从主文件重新读入已撤销摘要；新版只在撤销记录与加密恢复文件的内容指纹和文件身份均一致时读取未撤销部分。重试成功后仍保存原来的未删除摘要。中断于撤销记录确认之前则停止摘要读取，保留现场，不自动猜测要恢复哪些私人内容。同一尚在运行的会话可以在核对本轮恢复文件后重试；重启后的会话不能替未知中断猜测撤销对象。临时对话和普通本地学习仍可使用。

新的摘要确认只有收到持久化回执后才出现在已保存列表并进入模型上下文；并发确认与删除不将失败的确认混入后续快照。文件系统完全不可写、锁无法取得或撤销记录达到上限时，不能承诺删除已经持久完成，应保留失败提示并核对现场。上述保护不清除供应商或用户私下备份中的历史，也不承诺物理擦除磁盘。

仅当诊断显示 `recoverable: true`，核对所列 PID 已退出且所有相关宿主均已关闭，才用诊断的完整指纹显式恢复：

```sh
node scripts/recover-private-state.mjs --lock /absolute/plugin/data.json.credentials-write.lock --recover --expected DIAGNOSIS_FINGERPRINT --confirm-stopped
```

恢复将该锁改名为相邻的 `.recovered-<id>`，保留证据，不删除任何配置、凭据或临时草稿。随后重试受管理安装或重启插件，确认成功后再人工删除隔离的锁。PID 仍存活、权限不足、锁变化、符号链接、所有者内容缺失/损坏或未知文件存在时均拒绝自动恢复；没有超时抢锁或强制删除选项。此时保留现场，由人工核对所有者后处理。

这是受管理的配置保护，不是网络沙箱。历史 0.5.3 的手动「Tutor 与 Codex 协作」命令没有全局停用开关，仍可选择 Codex/OpenCode 或远程专家；不能仅靠这些设置保证该入口关闭，也不能阻止用户在旧版重新启用连接、直接打开远程资源或任意旧代码联网。需要严格断网时应使用系统断网措施，或选择已验证且支持新安全边界的兼容程序，而不要运行历史包。工具不会为封锁这些入口而改写 command/URL 或复制其他宿主凭据。

用户自行覆盖程序、复制整个旧配置或直接删除锁不在受管理恢复保证范围内。恢复脚本的合成文件测试不替代真实宿主升级—回退—重升验收。
