# Tutor 个性化形象与表情包规范（草案 v1）

日期：2026-09-28。范围：静态角色立绘与表情包；不包含动画、实时换脸或从私人记忆直接公开生成。

## 产品原则

每位用户可以有不同的 Tutor 形象。角色从用户明确授权的 Tutor 记忆中提炼视觉线索，再由用户审核设定与定稿图；不能把用户性格、年龄、性别、民族、健康或其他敏感属性当作推断依据。默认使用原创虚构角色，不生成用户或第三人的肖像。用户可以完全不使用记忆，改用手写设定、上传授权参考图或现有画板作品。

“鲸鱼娘”只用作**完成度的比较样例**：可辨识的整体轮廓、层次丰富的发型与服装、面部细节、配件、表情和统一的角色语言；不复制现有角色的面容、服装、配色组合、标识或画面。角色质量由视觉检查决定，不能用节点数替代。

## 创建流程

1. **选择依据。** 列出可用于形象设计的记忆类别（例如学习主题、偏爱的自然意象、双方共同命名的道具）。默认全部不选；用户逐项授权。生成前只提取非敏感的设计短语，不把完整对话、原文档或 Vault 路径发送给图像服务。每条线索标记来源类别、可撤回状态和“仅本地／可发给所选模型”。
2. **角色设定卡。** Tutor 输出 2–3 个不同方向，每张说明外形、轮廓识别点、性格表现、服装、道具、色板、禁用元素及所用线索。用户可编辑、删除线索或选择“完全从零设计”。这一步不写入正式形象库。
3. **定稿形象。** 用户选定一张设定卡后，生成全身正面、三分之四视角、侧面以及面部近景；先做低分辨率候选，再确认高分辨率定稿。每张保留模型／提示词版本、参考图授权与种子；原图作为不可变参考资产。生成失败或取消不替换当前形象。
4. **部件化。** 把已确认的定稿拆为背景、后发、身体、脸、眉、眼／瞳孔、嘴、前发、上装、下装、手臂／手、鞋、饰品、道具和效果。可编辑部分进入现有 `BoardVectorAsset` + `BoardCharacterDefinition`；难以可靠矢量化的材质以分层位图保留，不能虚称为可编辑路径。
5. **表情包。** 在锁定的角色设定版本上批量生成表情，先展示 4 张预览，再由用户挑选、修正和保存。每张表情都引用确定的形象版本、表情配方及几何或图像快照；更新形象不会改变旧表情或旧画板。
6. **使用与分享。** 用户可以在「表情素材」搜索、插入、移除、恢复与导出。公开导出默认移除记忆来源、私人提示词和 Vault 路径；是否展示作者名、设定说明及许可由用户选择。

## 角色设定卡（拟新增的独立数据，不修改旧画板 schema）

```ts
type TutorAvatarBrief = {
  format: "tutor-avatar-brief-v1";
  id: string;
  ownerScope: "local-user";
  status: "draft" | "approved";
  displayName: string;
  visualMotifs: string[];      // 由用户确认的非敏感意象，建议 2–5 项
  silhouetteMarkers: string[]; // 头形／发型／尾或披肩／道具等，至少 3 项
  palette: string[];           // 5–8 个 8-bit sRGB 色值，标注主／辅／强调色
  hair: string;
  face: string;
  outfitLayers: string[];
  accessories: string[];
  personalityInMotion: string[]; // 动作表现，不是对用户的人格诊断
  forbiddenElements: string[];
  approvedMemoryCueIds: string[]; // 本地索引；不得进入公开作品包
  referenceAssetIds: string[];
  consent: { cloudReference: boolean; publicDescription: boolean };
  createdAt: string;
};
```

`approvedMemoryCueIds` 只在本地草稿中存在。定稿形象保存经过用户确认的视觉描述、角色定义版本及资源哈希，不存原始记忆文本。删除或撤回线索后，未来生成不得继续使用它；已公开分享的文件无法远程撤回，界面必须说明。

## 视觉与结构下限

- 角色在 64 px 缩略图、透明背景、浅／暗背景中可辨识；正面和三分之四视角保留至少 3 个相同轮廓标记和一致的主色关系。
- 全身图至少包含分层发型、脸部五官、上下装或等价的多层服装、左右手、鞋或对应身体结构、至少 1 个有叙事作用的道具；服装和配件不能只是贴在单张图片上的装饰。
- 面部至少分离眉、眼形、瞳孔／视线、嘴形、脸红／汗／泪等微表情元素。沿用现有 `emotion / mouth / blink / gaze / micro` 五通道；同一通道的冲突按优先级处理，不能双重叠加出错。此拆分参考 [VRM 表情规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/expressions.md) 与 [Live2D 表情机制](https://docs.live2d.com/en/cubism-editor-manual/facial-expression-system/)，Tutor 不依赖其运行时。
- 首套建议 12 张：思考、疑惑、发现、鼓励、庆祝、安静、认真倾听、恍然大悟、抱歉并纠正、休息提醒、一起加油、完成任务。每张有可描述的眉眼嘴变化、姿势／手势和至少一个情境细节；不能只是换文字或在同一脸上加符号。
- 角色配方应复用一套稳定的发型、脸、服装和道具 ID。表情卡可独立改眉眼嘴、手势、构图和局部特效；修改其中一张不能改坏其余 11 张。至少 90% 的主要部件具名且可独立选择。
- 草稿图建议以 1024 px 以上生成与审查；表情导出提供透明 512 px PNG/WebP，同时保存可编辑源和角色版本。缩略图必须检查线条、文字和细节在 64／128 px 下是否可读。

## 安全、版权与验收

- 不因“根据记忆”就自动发送记忆给云端。首次使用需说明选中的线索和目标 Provider；每次生成只发送审核后的设定卡与用户选择的参考图。模型不可用时仍可手工设计和保存。
- 参考图、发型、服装、标识必须是用户自有、明确授权或许可兼容的素材；禁止以某个现成“鲸鱼娘”角色为复刻目标。保存作者、资源来源及许可信息。版权与隐私字段参考 [VRM 元数据规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/meta.md)。
- 用户至少能查看「使用了哪些线索」「将发送什么」「最终保存什么」，并能拒绝一个线索、重生成单张表情、回退形象版本、隐藏或恢复素材。
- 验收以至少 3 个不同设定进行盲看：角色一致性、画面完成度和表情可辨性各不低于 4/5；12 张中不得出现关键肢体缺失、服装凭空变化或未授权个人信息。保存—重开—导出后的外观和版本引用一致。

## 与现有工程的落点

现有 `TutorCharacterProfile` 已支持内置、上传、共创及不可变版本；`BoardCharacterDefinition` / `BoardCharacterRecipe` 已有部件、姿势和五通道表情。下一开发切片应先做 `TutorAvatarBrief` 的本地草稿与审核界面，再接记忆线索选择器和生成 Provider。不要在没有审核门禁时把学习记忆直接拼进提示词。当前表情面板的「移除」仅修改 `characters/library.json` 的可见性，不删除资产或历史引用；内置卡片按具体表情隐藏，自定义素材按整个 profile 隐藏，可在「已移除」恢复。
