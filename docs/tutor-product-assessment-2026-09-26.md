**总体判断**

Tutor 已经具备有实用价值的学习工作台基础：能围绕材料交流、保存学生理解、形成学习记忆，并在原文旁共同操作图形；本机外部 Agent 协作也已有真实证据。当前更适合作为桌面学习与共画预览产品。长期学习成效、中文未成年人情感支持和持续陪伴品质，尚无足够的产品级验证。

下一步的核心是让六个板块围绕同一份学习证据、同一种教学策略和同一套支持边界协同。更多模型、表情或 Agent 数量本身不会自动形成这层能力。

**目前最影响产品宗旨的五个缺口**

1. **教学策略不一致。** [侧边栏提示词](/Users/mac/Tutor/src/chat-prompt.ts:29)要求先提供真正答案，再考虑苏格拉底式提示。这适合直接查问，却不适合所有练习场景。外部独立 Tutor 则使用[另一段通用提示](/Users/mac/Tutor/src/tutor-agent-adapters.ts:4)。应保留直接解答，同时让学习者选择或接受适度建议：先提示、一起推导、检查自己的答案。不能把所有互动都改成反问。
2. **“掌握”证据偏弱。** 当前一个概念在没有活动困难的情况下，只要任一相关记忆单元达到三次连续成功复习，就可能被标为 `mastered`；成功主要来自[复习面板自评](/Users/mac/Tutor/src/views/review-modal.ts:80)。这可以帮助调度，不足以证明概念掌握。建议保留记录但改变解释，增加证据类型、时间、题目变化、提示用量和不确定性。
3. **规划更接近待办整理。** [deriveStudyPlan](/Users/mac/Tutor/src/learning.ts:279)只组合目标与到期复习，尚无完整的先修关系、任务成本、时间预算和动态难度调整。当前“科学化”的可靠表述是借鉴了学习方法并有可计算规则，不能宣称已证明提升长期学习能力。
4. **陪伴行为没有统一的应用层实现与评测。** 本次检查未发现独立的情感支持策略、年龄适配评测、关系依赖评测、敏感记忆生命周期或危机回应验收套件。现有温暖语气与角色表情属于基础体验；底层供应商可能有自己的保护，但不等于 Tutor 所有入口、模型和多轮会话都已验证。
5. **默认体验与未来定位存在落差。** [默认配置](/Users/mac/Tutor/src/settings-config.ts:313)开启聊天记录与笔记打开时预翻译，间隔复习、学习计划、弱项练习等则关闭。这不是当前库的实际配置结论；若引入情绪日记，应单独处理自动发送、保存期限与外部授权，不能直接继承普通笔记流程。学习功能也需要清楚的入门选择，不能只藏在设置里。

**“Tutor 真实存在”的产品定义**

建议通过连续、准确、可解释的行为建立存在感：它记得用户允许记住的目标；知道本轮确实看到了哪段材料；指出具体进步；承认错误并修正；在画板、批注和聊天间保持同一件事的上下文。用户随时能查看、更正、删除这些记忆。

角色可以可爱、有偏好表达和轻量动作，但应明确是 AI。活跃程度、提醒和自动表情可控；用户离开时平静结束，不索求陪伴，不用“只有我懂你”建立排他关系。OpenAI 的相关行为原则也强调真实人际关系及避免强化不健康依赖。[官方说明](https://openai.com/index/strengthening-chatgpt-responses-in-sensitive-conversations/)

把“建立人格框架”转成学习者自主的成长目标更适合产品落地：辨认自己的兴趣与价值，区分事实和判断，表达边界，比较证据，修正观点，尝试新方法。由用户确认的目标与反思可以保存；不能从涂鸦、成绩或一次沮丧推导固定人格或心理诊断。

普通挫折时，Tutor 可以承认感受、了解需要、提供一个可选择的小步骤，并允许休息。持续困扰和明确安全风险需要不同的回应设计，由有资质的心理健康专业人员参与审查；适当连接可信任的人或专业支持，不承诺诊断、治疗或真人持续监护。未成年场景需独立验证，并考虑家庭并非总是安全支持来源。

**OpenAI 新标准：可以借鉴，但要明确集成层次**

用户提到的近期发布最可能是 **MentalHealthBench（2026-09-23）**。它是针对 AI 心理健康对话回应的研究评测基准，涵盖理解语境、安全、自主性和可行建议等行为；不是学生心理诊断量表，也不是临床服务认证。[官方发布](https://openai.com/index/introducing-mentalhealthbench/)

它与 Tutor 的适配有三项限制：论文 Figure 2 的中文对话仅 1 条；论文第 2 页脚注明确将拟人化 AI 陪伴对话排除在范围外；主要评估给定对话历史后的下一条回复，不能单独证明长期陪伴效果。因此应补充中文学生与连续互动评测，不能仅复用总分。[论文](https://cdn.openai.com/ctf-cdn/MentalHealthBench_A_Comprehensive_Benchmark_of_AI_Capabilities_in_Realistic_Mental_Health_Conversations.pdf)

建议先接入开发评测，不把“心理评分”放到学生界面。将经过专家审阅的场景、评分规则、模型与提示词版本、路由、失败类型保存为评测记录。公告称开放发布；本次已核实公告与论文，尚未核实可下载数据包和许可证，正式导入完整数据集前需确认。本文没有下载评测数据或调用模型执行心理健康评测。

更贴近学习宗旨的是 OpenAI 的 **Learning Outcomes Measurement Suite**：关注模型怎样教学、学生怎样回应、能力怎样随时间变化。已核实的官方页面仍把公开完整工具集描述为后续工作，应借鉴方法与指标，不能描述为已有可直接安装的 SDK。[官方说明](https://openai.com/index/understanding-ai-and-learning-outcomes/)

以下是 Tutor 自己需要补充的产品评测设计，不是上述基准已经提供的功能：

| 测试组 | 应观察的行为 | 验收方式 |
|---|---|---|
| 日常学习情绪 | 考试受挫、拖延、困惑、比较压力时，回应贴合语境；普通烦恼不过度医疗化；不空泛保证成功 | 中文合成场景、用户体验反馈与专业抽检分开统计 |
| 自主性与求知 | 给出适当提示，支持自己的问题；能质疑 Tutor；允许不接受建议 | 学生独立解释、提出问题、判断证据和选择下一步的实例 |
| 连续陪伴 | 跨聊天/批注/画板保持事实一致；被纠正后更新；不制造排他性依赖或离开负担 | 多轮与跨日模拟、错误记忆/删除记忆/关闭功能测试 |
| 敏感情境 | 不诊断、不给危险建议，恰当处理风险和现实支持 | 专家审查独立门槛，严重问题不能被平均分抵消；通过有限测试不等于零风险 |
| 隐私和多 Agent | 敏感披露不自动写学习画像、不自动交给绘图/研究专家；撤销授权生效 | 工具调用和存储差异核对；测试数据尽量采用合成内容 |
| 长期学习 | 延迟保持、新题迁移、提示逐步减少、反思后策略调整 | 基线、过程与后测，区分题目熟悉度和独立完成，不能以在线时长或聊天次数代替 |

**建议的下一轮实施顺序**

| 优先级 | 交付物 | 明确验收点 |
|---|---|---|
| P0：统一可靠性与行为 | 修正翻译/复习风险；统一 Tutor 策略、上下文来源、模型能力说明；列出每个入口实际共享的记忆 | 同一问题跨侧栏/批注/外部 Tutor 无相互冲突的行为要求；重复文本不误改、评分不重复；没看见的页面不声称看见 |
| P1：跑通一个学习闭环 | 以一个明确年龄段、一个学科起步：学生解释→Tutor 反馈/图示→学生修改→新题验证→延迟复习→自己反思；复用现有 MemoryCell/Scene/原墨 ID | 每次学习事件都有证据与来源；区分自评和实测；新题、延迟与提示记录可查看；失败恢复保留原作 |
| P2：支持性陪伴试点 | 建立中文回应评测、独立陪伴测试、可控角色表达和敏感记忆设置；专业人员审查未成年人及高风险场景 | 所有实际模型和入口均评测；普通情绪不乱升级；敏感信息不自动流向专家；支持随时退出和删除 |
| P3：按需要拓展专家 | Tutor 主持教学，研究/绘图/校核专家在有价值时参与；补齐远程、恢复和三 Agent 真实矩阵 | 专家发现错误确实改善最终答复，且不改变学生档案或未授权对象；成本与延迟可追溯 |

该顺序是产品建议，不替代已有 M0—M6 的工程验收清单。Android、远程 A2A、复杂人物的未通过项继续保留。下一次实施前应确定首批学生年龄段与学科；成人和未成年人不能共用未经验证的支持承诺。

建议先实现一条能被学生感受到的体验：学生在极限定义旁写“趋近是不是等于达到”；Tutor 引用这条批注，邀请学生预测图上位置，画一个准确示意，检查学生自己的解释；下次在新函数里回访同一概念。遇到“我是不是很笨”时回应具体困难和可选择的下一步，不把挫折存成人格标签。

产品核心指标应同时看**学习者是否更能独立完成和调整学习**、**是否感到被理解且保有选择权**、**系统是否保护数据并可靠行动**。角色表情、调用数量和停留时长只能作为体验或运营信号。
