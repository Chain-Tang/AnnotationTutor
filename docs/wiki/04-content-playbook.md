# 04 · 内容形式模板

三种常见内容形态的结构模板 + 可直接执行的演示脚本。所有演示步骤都基于 [02 · 核心功能拆解](02-features.md) 中的真实能力。

## A. 短视频（60–120 秒，抖音/B 站/Reels）

**结构：钩子（5s）→ 冲突（10s）→ 演示（60s）→ 记忆点收尾（10s）**

| 节拍 | 画面 | 口播要点 |
| --- | --- | --- |
| 钩子 | 屏幕上一段划了荧光的高亮 | 「你的高亮，三天后还看得懂吗？」 |
| 冲突 | 翻找另一个 App 里的笔记，找不到出处 | 「笔记和原文分家，等于没记。」 |
| 演示 1 | Obsidian 中选中文字 → `⌘⇧L` → 便签弹出 → 写下理解 | 强调「理解留在原文旁边」 |
| 演示 2 | 点击高亮重新打开便签；鼠标移开按钮自动隐藏 | 强调「安静得像便签」 |
| 演示 3 | 请求 AI 点评 → Agent Review 区段出现判断（对/部分对/错） | 「AI 检查我读懂没有」 |
| 演示 4 | 「Review due cells」弹出到期复习卡片 | 一句带过 SM-2 与 Anki 同源 |
| 收尾 | 展示 `Agent Memory/` 目录树 | 「全部是普通 Markdown 文件，没有数据库。」 |

**备选钩子（PDF 向）**：「导师发的论文，我一个字都没改，但所有批注都在——批注存在 PDF 外面。」

## B. 图文（小红书 6–9 图 / 公众号配图段落）

推荐页面顺序：

1. 封面：hero 概念图或干净截图 + 标题钩子（见 03 篇）
2. 痛点图：高亮与笔记分家的示意图
3. 功能图：选中 → 便签 → 写理解 三连
4. 功能图：点击高亮回看 + 页边可拖动便签
5. 闭环图：引用仓库 `docs/assets/learning-loop.svg`（阅读→批注→反馈→记忆→复习）
6. 目录树图：`Agent Memory/` 结构，强调纯文件
7. 结尾：安装信息卡（Obsidian 1.12.4+ / 桌面端 / MIT / GitHub 仓库名）

**文案注意**：AI 能力必须写「需自行配置模型引擎」，避免读者装完发现不能直接用 AI 而差评。

## C. 长文/深度评测（公众号长文 / B 站 10 分钟）

建议章节骨架：

1. 从「收藏≠学会」切入，引出主动回忆与间隔重复（学习科学背景）
2. 产品理念：像便签一样自然 / 理解留在原文旁边
3. 实测三条材料：Markdown 笔记、表格单元格、PDF（各自演示锚定与恢复）
4. 学习闭环完整走一遍：批注→点评→记忆单元→场景→笔记本→复习；展示 frontmatter 里的 `ease/intervalDays/dueAt`
5. 双引擎接入体验：Direct API vs OpenCode（如实记录验证步骤）
6. 进阶彩蛋：灵感画板对话画图、AGENTS.md 与外部智能体
7. 边界与不足：照实引用 06 篇「当前边界」，给出适合/不适合人群

## 演示环境准备清单

- Obsidian 1.12.4+（建议录屏前隐藏个人插件列表与其他 Vault 内容）
- 干净示例 Vault：一篇 Markdown 论文笔记 + 一个含重复文字的表格 + 一份文字可选的 PDF
- 引擎：准备一个可用 OpenAI 兼容端点（录点评用），或已登录的 opencode CLI
- 语言：按目标受众切换插件界面语言（中英日繁四种）
- 隐私：演示文档**不要用真实论文/真人笔记**，录屏检查侧栏、路径、密钥字段

## 版本口径

发布内容中标注版本时，以安装时的 `manifest.json` 版本与 GitHub Releases 页面为准；源码可能领先于发行版，演示到的功能若未发行，应说明「需从源码构建」。
